# v0.4.1 — 修复框选区域（取消后主窗口消失 / 坐标不是全局坐标）

修掉截图翻译的框选环节两处真实缺陷，并把这条链路补上日志（原来一行日志都没有，出问题无从查起）。

## 修了什么

| # | 缺陷 | 症状 | 修复 |
| --- | --- | --- | --- |
| 1 | **取消框选后主窗口不再出现** | 按 F10 / 点「框选区域」后如果按 Esc 或右键取消，主窗口被 `hide()` 掉了却没有任何路径把它还原 —— 用户会以为程序消失了，只能重启 | 补上 `cancelled` / `destroyed` 回调 + 幂等的 `_restore_after_pick()`；框选窗口增设 `WA_DeleteOnClose` 保证 `destroyed` 一定发出；再按一次 F10 = 取消 |
| 2 | **框选矩形用的是控件局部坐标** | 多显示器、或虚拟桌面原点不为 (0,0) 时，保存下来的截图区域整体偏移（截到别处） | 改用 `ev.globalPosition()` 计算**全局逻辑坐标**，绘制时再换算成局部坐标；裁剪也改在全局空间做 |
| 3 | 框选链路完全无日志 | 出问题只能靠猜 | 现在会记录：选择器已显示（含几何/虚拟桌面范围）、框选起点、框选完成的全局矩形、保存的 logical+physical+屏幕、取消、过大/过小被忽略、创建失败异常栈 |
| 4 | 热键注册失败几乎没有提示 | 按 F9/F10 毫无反应 | 卡片状态栏会黄字提示「热键注册失败：可能已有另一个本程序在运行，或被其它软件占用」；日志给出同样原因 |

## 关于"按了没反应"

如果 F9/F10 完全没反应，先看 `data\logs\sc_translator.log` 有没有这一行：

```text
WARNING [sc_translator.hotkeys] 热键注册失败 id=20737 vk=0x78（可能被其它程序占用）
```

出现它就说明**Windows 层面没把热键给到本程序**——最常见的原因是**上一个实例还在运行**（RegisterHotKey 对同一组合只允许一个进程），
或者在用别的软件占用了 F9/F10。处理方法：退出所有本程序实例后重开，或在卡片里把热键改成别的键。
