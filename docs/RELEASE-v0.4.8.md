# v0.4.8 — 窗口可以自由调整大小了：125% 缩放下不再"显示不全"

用户反馈：**125% 缩放下页面显示不全**。查下来是主窗口被内容"钉死"了。

## 下载

| 文件 | 说明 |
| --- | --- |
| `SCTranslator-v0.4.8-win64.zip` | 解压到任意目录 → 双击 `SCTranslator.exe` |

## 原因（实测数字）

主窗口的 `minimumSizeHint` 是 **1430 × 1239** —— 由各卡片与多个文本框的最小高度叠加而成
（输入区 280、回话区 120、结果区 130、游戏码 70×2、截图原文/译文 80×2 …）。后果：

- 窗口被**强制撑到 1430×1239**，而 1080p @125% 的可用高度只有约 **864**（逻辑像素）→ **底部落在屏幕外**；
- 想缩小也缩不动：`resize(700, 500)` 之后尺寸会被最小高度**弹回 1430×1239**——这就是"固定窗口大小"的由来。

## 修复

| # | 修复 | 说明 |
| --- | --- | --- |
| 1 | **整页放进滚动区** | 所有卡片包进 `QScrollArea`（`widgetResizable`，按需出现滚动条）。窗口最小尺寸从 **1430×1239 降到 38×66**——想缩多小就多小，缩小的内容用滚轮看 |
| 2 | **初始尺寸收敛到屏幕内** | 默认仍是 980×880，但会按当前屏幕可用区域收敛一次（125%/150% 不会再一开局就超出屏幕） |
| 3 | **记住窗口大小/位置** | 新增设置 `main_geometry`：关闭时保存、下次启动恢复；若历史位置/尺寸超出当前屏幕（换显示器、拔掉外接屏）会自动收敛回屏幕内 |

实测（`QT_SCALE_FACTOR=1.25`）：

```text
改前: minimumSizeHint 1430x1239 | 实际 1430x1239 | 底部超出屏幕 True  | resize(700,500) -> 仍是 1430x1239
改后: minimumSizeHint   38x66   | 实际  600x600  | 底部超出屏幕 False | resize(700,500) -> 700x500
```

## 测试

新增 `tests/test_main_window.py`（5 项）：整页可滚动、窗口能自由缩放（三组尺寸）、
初始尺寸不超出屏幕、尺寸跨重启记住、历史几何超屏时收敛回屏幕内。
测试总数 **214 → 219 passed, 1 skipped**。

- 界面文案未变，三语无需改动。
